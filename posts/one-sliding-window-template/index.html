One sliding-window template, many problems

The two pointers, when the window grows, and the exact moment you should shrink it.

{ }

Sliding windows feel like a bag of tricks until you see the invariant. A window is just a contiguous range that maintains a property. The algorithm grows the right edge and shrinks the left edge only when the property breaks.

When a window fits

  • The answer is about a contiguous subarray or substring.
  • Adding an element is easy to track; removing the leftmost element is also easy.
  • The property is monotonic: once the window is invalid, adding more cannot fix it.

The template

example.pyPython
1def longest_unique(s):2    last = {}3    left = 04    best = 05    for right, ch in enumerate(s):6        if ch in last and last[ch] >= left:7            left = last[ch] + 18        last[ch] = right9        best = max(best, right - left + 1)10    return best

The invariant is simple: the window s[left:right+1] has no repeated characters. When a duplicate appears, jump the left edge just past its previous position. The window never moves backward, so the total work is linear.

Common mistakes

  • Shrinking with a while loop when a direct jump is possible. Both can be correct, but know which one you are writing.
  • Forgetting to update the best answer after the shrink, not before.
  • Using a window when the problem is not contiguous. Subsequences are a different family.

Practice the template on three questions: longest substring without repeats, minimum window containing a set of characters, and maximum sum of size k. Same skeleton, different state.
